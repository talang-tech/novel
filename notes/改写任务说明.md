# 空转改造任务说明（子代理必读）

## 目标

消除「动作空转」，让每一章通过体检脚本。

```bash
cd /root/novel && python3 scripts/check_chapter.py chapters/第XX章-标题.md
```

退出码必须为 0。脚本会打印当前数值。

## 硬性配额（每章）

| 句式 | 上限 |
|---|---|
| 没有说话/没有回答/没有接话/没说什么/没有出声 | ≤ 3 |
| 站起来/坐下/走到/走出/走进/走回 | ≤ 8 |
| 看了一眼/看了看 | ≤ 6 |
| 点了点头/点点头/「嗯。」 | ≤ 5 |

同时必须保持：
- **字数 4800–6700**（目标 5000–6500，允许 ±200 浮动）
- 对话段数 40–130

⚠ **删掉空转后必须补回等量的有信息内容**，否则字数会跌破下限。
已有两章犯过这个错（第 04 章掉到 4843、第 12 章掉到 4695）。

## 三条改写规则

### 规则 1：沉默必须带信息

「陈稳没有说话。」全书出现 79 次，是最大问题。每处换成**具体的、带信息量的动作或内心事实**，且每处都不一样。

- ✗ 陈稳没有说话。
- ✓ 陈稳把杯子往左边推了两厘米，推到刚才的位置。
- ✓ 陈稳知道能合。他在二号楼建的那三个视图，六十八行 SQL，本来就是给对账模块喂数据的。但他也知道，一旦说能合，这两个方案就变成一个方案，一个方案只有一个负责人，而数据治理的负责人是易文。
- ✓ 这件事陈稳知道。张磊上周五给他发过消息，他回了一个「好」。他没有告诉易文。

可以写陈稳**知道什么、想起什么具体事实/数字/人名**，但不能写「他感到委屈」这类直接情绪解释。

### 规则 2：位移一律省略，直接切场景

除非路上真的发生了事。

- ✗ 他关掉电脑，站起来，走到纪衡的办公室门口，门开着，纪衡坐在办公桌前。
- ✓ 纪衡的办公室门开着。

### 规则 3：「看」要看出具体东西，看不出就删

- ✗ 他看了一眼监控大盘。
- ✓ 结算成功率百分之九十九点九九，比昨天高了两个万分点。

## 顺手加压三件事

1. **开场 300 字内要有一个具体的麻烦**（告警、邮件、一句话、一个数字）。禁止从「起床/通勤/到工位/看监控大盘」开场。
2. **每章至少一次信息不对称**：用「这件事陈稳知道」「他没有告诉X」点出来。
3. **章末落在画面或动作上，指向下一章**。禁止「他知道，这件事还没有结束」这类总结句。

## 严禁破坏

- 人名固定：陈稳、梁栋（老梁）、纪衡、蒋辉、易文、顾源、何晚、张磊、周其正、技术 VP
- 废弃旧名不得出现：陈屿/老邵/韩澈/罗嘉/苏芩
- 不得增加情绪失控场面（摔/吼/哭/当众顶撞）。相关章节失控配额为 0
- 不得让反派降智：蒋辉、纪衡的判断经常是对的，这是本书核心难受之处
- 技术细节必须真实可信，保留原文的 SQL/日志/commit message/监控读数
- 不得提前用掉后面章节的事件
- 白描风格：少形容词、少比喻、不解释心理、对话短（单句一般不超 25 字）

## 工作流程

1. 读 `setting/03-文风基线与写作规约.md`（第六、七、八节）
2. 读 `notes/进度追踪.md` 中你负责章节的「第 XX 章新增」段落
3. 逐章：读原文 → 用 patch mode=replace 逐段改（**不要整文件重写**）→ 跑体检 → 不通过继续改
4. 全部通过后再跑一次确认

**不要 git commit**，改完即可。
