# 第十三章 · 易文

九月二日，星期三，上午九点。

陈稳到公司，打开电脑，打开监控大盘，绿的，平的，结算成功率百分之九十九点九九，拦截器正常，连接池使用率百分之六十七。他看了一眼，打开邮件，看到纪衡的回复：OKR 已收到，下午两点会议室，跨部门项目会。

他关掉邮件，打开 IDE，打开结算对账模块的代码，翻到核心比对方法，四百多行。他看了一遍，然后在一张空白的纸上画了三个框：结算系统、接口层、营销对账服务。他在接口层旁边写了一个问号。

下午两点，他走到三楼会议室，推开门。纪衡坐在主位，面前放着一个笔记本。蒋辉坐在纪衡左手边，面前摊着一份打印好的材料，三四页，每页都有划线。对面坐着一个他从没见过的男人，戴眼镜，三十五六岁，穿格子衬衫，袖口卷到小臂。纪衡右手边空着一个位置。

陈稳坐下来。

"人到齐了。"纪衡说，合上笔记本，然后介绍了周其正和项目情况：营销技术部要做一套新的营销结算对账系统，把现有的对账逻辑从结算系统里拆出来，单独做一个服务，结算组只需要提供数据接口。

"蒋辉，你怎么看。"

蒋辉翻了一下面前的打印材料，抬起头。他说思路没问题，SLA、数据延迟容忍度、数据量预估确认清楚就行。周其正说 SLA 三个九，延迟三十分钟以内可接受，日均三万笔，月末六到七万。蒋辉在材料上划了一道，说数据接口层可以在一周内出第一版，两周内接入测试。

"陈稳。"纪衡说。

"嗯。"

"你对这个方案有什么看法。"

陈稳看了一眼蒋辉面前那几页纸，上面有打印体的标题：营销结算对账系统解耦方案，落款是周其正，日期是九月一日。他问数据接口层拆出来之后跟现有的结算对账模块是什么关系。周其正说并行，营销侧用新的，结算侧用现有的。陈稳又问两边数据不一致怎么办，接口层由谁维护。周其正说接口层由结算组维护，数据一致性由结算组保证。

"如果营销侧改规则，接口层没有同步更新，数据对不上，算谁的。"

周其正没有立刻回答，端起面前的水喝了一口，说这个需要约定，但还没有想好怎么约定。

纪衡敲了一下桌面，说先定接口层，数据一致性后面再讨论。蒋辉牵头，陈稳配合，两周内出第一版。

蒋辉说没有。陈稳也说没有。

会议散了。陈稳走到门口，听到身后有人叫他。他回头，看到周其正站在会议室门口，问他数据一致性的问题以前遇到过没有。他说遇到过，写了一个拦截器做运行时校验。周其正点了点头，没有说话，转身走了。

陈稳走回工位，坐下来，打开电脑，打开记事本，写了一行：营销结算对账系统解耦，蒋辉牵头，我配合。他盯着这行字看了一会儿，合上记事本，打开 IDE，继续看代码。

下午五点，蒋辉发了一封邮件，抄送纪衡、周其正、陈稳。标题：营销结算对账系统解耦——数据接口层技术方案（初稿）。附件是一个 Word 文档，十六页。

陈稳打开附件，从头到尾看了一遍。蒋辉的方案写得很完整，最后一条写的是"依赖结算组现有拦截器机制，由陈稳配合接入"。他把这句话看了两遍，关掉文档，打开记事本，写了一条：他写了十六页，里面有我的拦截器。他盯着这行字看了一会儿，删掉，重新写了一行：下午自己问易文。

他拿起手机，给易文发了一条消息，说蒋辉的方案发了，十六页，里面有我的拦截器。

易文没有回复。

他放下手机，站起来，收拾东西，走出公司，去地铁站。地铁上，他站在车厢里，抓着扶手，看着窗外黑色的隧道。他想起今天下午的会议，想起蒋辉面前那几页打印好的材料，想起周其正说"这个需要约定"的时候声音里的停顿。他想起自己坐在椅子上，面前什么都没有。

列车到站，他下车，走回小区，上楼，开门，换鞋，走进客厅，坐了一会儿，拿起手机，看到易文的消息，发在四十分钟前：明天中午，食堂，十二点。

他回了一个字：好。然后站起来，走进厨房，打开冰箱，拿出牛奶，倒了一杯，喝了一口，凉的，胃没有反应，喝完，把杯子洗了，放在架子上。

第二天上午，十一点五十分，陈稳端着餐盘在食堂里找了一圈，看到易文坐在靠窗的位置，面前放着一碗面，已经吃了一半，筷子搁在碗沿上。他走过去，坐下来。

易文问他，昨天说蒋辉的方案里有你的拦截器，你做了什么。他说，他写方案的时候把拦截器写进去了，说由我配合接入。易文问他之前知不知道，他说不知道。

易文没有接话，低头吃了一口面，嚼完，咽下去，放下筷子，然后说："你知不知道，你昨天下午被叫去那个会议，是做什么的。"

"……配合。"

"不是。"易文说，"你被叫去，是因为这个项目需要你。不是因为蒋辉需要你，是因为纪衡知道，没有你，这个项目做不了。"

陈稳没有说话。

"你知不知道，你昨天下午在会议室里说的那句话，是什么。"

"哪句。"

"'数据一致性由谁保证'。"

"嗯。周其正没有回答你的问题，不是因为他不想回答，是因为他答不出来。你问完那句话，他才知道，不简单。你知不知道，你问完那句话之后，蒋辉做了什么。"

"什么。"

"他去找了周其正，说拦截器的事，他来做。"

"你怎么知道。"

"周其正跟我是同一个项目组出来的。"易文说，又吃了一口面，嚼完，咽下去，"他刚才给我打了一个电话，说你们结算组的蒋辉做事很主动，看起来是那个项目最靠谱的人。然后他说，结算组还有一个同事，叫陈稳，问了一个数据一致性的问题，但没想好怎么回答。"

陈稳没有说话。

"你的问题是对的。"易文说，"但你没有把问题变成你的。你问了一个问题，周其正回答不了，然后你坐下了，等别人回答。你等到了蒋辉回答。他回答的不是你的问题，他回答了'这个项目怎么做'，不是'数据一致性怎么保证'。他把你的问题盖过去了。"

"那做什么。"

"你说了算。你问完问题，你知道答案是什么，你说出来。你说，数据一致性由拦截器保证，拦截器由我负责，接入方案我出。你说完了，这个事就是你的了。"

陈稳没有说话。易文看着他，问听懂了没有。他说听懂了。

"你听懂什么了。"

"问完问题，要说答案。把事变成自己的。"

易文看了他一眼，没有接话，低头吃完了剩下的面，把汤喝完，把碗放在一边，问他下午有没有事。他说没有。易文说，那你来我工位一下，我给你看个东西。

易文端着餐盘走了。陈稳坐在椅子上，看着自己面前那盘还没怎么动的饭，拿起筷子开始吃，饭已经凉了，牛肉有点硬，青菜有点咸。他吃完了，把餐盘放到回收口，走出食堂。

他在电梯口等电梯，看到蒋辉从电梯里走出来，手里拿着一个文件夹。蒋辉问他看到方案了没有，他说看到了。蒋辉说有什么意见可以提。他说，数据接口层的字段定义跟现有的结算对账结果表的字段不一致，需要对齐。蒋辉停了一下，看着他，说好，我回去改，然后走了。

陈稳站在电梯口，看着蒋辉的背影消失在走廊拐角，然后按了电梯，上楼。

他走到易文的工位，在数据组那一层，走廊尽头，靠窗的位置。易文的工位上堆着几本书，《数据分析实战》《SQL 反模式》《用数据讲故事》。桌面上放着一个笔记本，翻开，里面写满了数字和简写。

易文坐在工位上，面对屏幕，屏幕上是数据看板，蓝底白字。她看了一会儿，关掉，转过来，问他刚才是不是说蒋辉的方案里字段定义跟结算对账结果表不一致。他说是，有四个字段对不上：商户 ID 在结算系统里是 varchar(32)，蒋辉写的 int；结算金额用 decimal(18,2)，蒋辉写的 decimal(10,2)；对账时间戳用 datetime，蒋辉写 timestamp；状态字段有七种，蒋辉只写了三种。

易文没有说话，看着他，然后说："你刚才在电梯口，告诉他了。"

"嗯。"

"你告诉他了，他回去改，改完，这个方案就是他的。你为什么不自己写一个方案。"

"……我没有时间。"

"你没有时间，是因为你没有把时间花在对的事情上。"

陈稳没有说话。易文问他昨天下午回工位之后做了什么，他说看代码，结算对账模块，四百多行，可以对账逻辑拆成两个部分，数据加载和比对执行，数据加载可以单独调用，不需要每次都跑完整对账。易文问他写了没有，他说写了。易文让他拿来看看。

陈稳拿出手机，打开 IDE，找到昨天写的方法，递给易文。易文接过去，看了一遍，沉默了几秒，然后把手机还给他。

"你写的是对的。但你没有用。你写了一个优化方案，然后你把它存起来了。你没有提交，没有发邮件，没有告诉任何人。你写的东西，总是出现在别人的方案里。"

陈稳没有说话。

"你听懂了没有。"

"……听懂了。"

"你听懂什么了。"

"写了要说。写了要变成自己的。"

易文看了他一眼，没有说话。她转过去，面对屏幕，打开一个文件，然后说："你过来看。"

陈稳走过去，站在她旁边，看着屏幕。屏幕上是一个 Excel 表格，列名是：项目名称、负责人、预估工期、技术依赖、业务价值。里面有几行他认识——"营销结算对账系统解耦"，负责人蒋辉，预估工期两周，技术依赖：结算组数据接口层、结算组拦截器。

"这是什么。"

"周其正的项目资源表。他做项目之前，先拉一张表，把依赖和负责人列清楚，然后找资源。你看到没有，蒋辉是负责人，你是技术依赖。你在这个项目里，是一个依赖项，不是一个人。"

陈稳看着那行字，没有说话。

"你知道为什么吗。"

"……不知道。"

"因为你在那个会议上，没有说任何一句话，能让周其正记住你。你问了一个问题，但他记住了蒋辉的方案。你没有把你的名字和任何可交付的东西绑在一起。"

"那下次带什么。"

"你写的方案。不用多，三页纸就够了。你写清楚，数据加载部分由你负责，拦截器接入由你负责，数据一致性方案由你负责。你写完了，发出去，这个项目就有你的名字了。"

陈稳没有说话。易文问他听懂了没有，他说听懂了，带方案去开会，方案上要有我的名字。

易文关掉 Excel，转过来问他，拦截器还在跑吗。他说在跑，全部通过，零资损。易文说，你写一个报告，把拦截器的数据拎出来，不要写技术实现，写业务效果，写完了发给我看。他说好。

陈稳走回自己的工位，坐下来，打开电脑，打开数据库，查询拦截器上线以来的全部数据。他写到文档里：上线运行天数，四十三天。累计拦截请求数，四万二千一百七十六次。通过率，百分之百。资损，零。触发告警次数，零。

他写完了，看了一遍，数字是对的，但看起来像是一份技术周报。他想起易文说的话，把数字重新翻译了一遍，删掉了一半，最后只留了一句：四十三天，零资损，零人工介入。

他保存了文档，没有发给易文。他打开记事本，写了一条待办事项：发给易文看拦截器报告。然后关掉，站起来，走到茶水间，倒了一杯水，喝了一口，凉的，胃缩了一下，他没有放下，继续喝，喝完，把杯子放在水槽里。

下午五点，他收到蒋辉的消息：数据接口层字段定义，已修改。附件是一个新版本的 Word 文档。

陈稳打开附件，翻到字段定义那一页，商户 ID 已经改成了 varchar(32)，结算金额改成了 decimal(18,2)，对账时间戳改成了 datetime，状态字段改成了七种。他看了一遍，关掉文档，回复了一个字：好。

他放下手机，打开 IDE，打开昨天写的数据加载方法，加了几行注释，然后提交了一个 commit。

```
commit d4c5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3
Author: Chen Wen <chen.wen@henglan.com>
Date:   2026-09-02 17:42

feat: 对账模块数据加载方法拆分，支持单独调用

将核心比对逻辑拆分为数据加载和比对执行两个阶段。
数据加载方法可独立调用，为后续接口层提供数据支持。
```

他推送了，关掉 IDE，站起来，收拾东西，走出公司，去地铁站。

地铁上，他站在车厢里，抓着扶手，看着窗外黑色的隧道。他想起易文今天说的那些话，想起她说"你写的东西，总是出现在别人的方案里"，想起她说"你在这个项目里，是一个依赖项，不是一个人"。他想起自己今天下午写的那份拦截器数据报告，四十三天，零资损，零人工介入。他想起他在电梯口对蒋辉说"字段定义不一致"，蒋辉说"好，我回去改"，然后他真的改了，改完，发回来了。

列车到站，他下车，走回小区，上楼，开门，换鞋，走进客厅，坐了一会儿，拿起手机，看到易文的消息，发在十五分钟前：报告写好了吗。

他回了一个字：写了。易文说，发我。

他打开邮件，把拦截器数据报告发给了易文，正文一行：附件。他发完了，放下手机，站起来，走进厨房，打开冰箱，拿出牛奶，倒了一杯，喝了一口，凉的，胃没有反应，他喝完，把杯子洗了，放在架子上。

他走回客厅，坐下来，拿起手机，看到易文的回复，不到两分钟。她说第一段太长，删掉技术细节，只留数字。第二段跟第一段重复。加一句对比：上线前四十三天发生过几次事故。

陈稳看完，没有回复，打开电脑，打开拦截器数据报告，把第一段删掉了一半，把第二段合并到第一段，在最后加了一行：上线前四十三天，营销结算适配器发生过一次事故，涉及十一个系统，长事务回滚五千三百三十六条。上线后四十三天，零事故。

他写完了，保存，发回给易文。

易文没有回复。

他等了一会儿，放下手机，站起来，走到窗边，看着对面那栋楼，晚上，窗户亮着，一格一格的。他看了十一个月的那扇窗，还是黑的。他看了一会儿，走回客厅，坐下来，打开电脑，打开蒋辉发来的那份方案，从头到尾看了一遍。十六页，字段定义、SLA、异常处理、数据一致性。他看完了，然后新建了一个文档，开始写。他写了一份数据接口层接入方案，三页纸。第一页：数据加载部分，由他负责，方法已写好，可单独调用。第二页：拦截器接入，由他负责，已有上线后四十三天运行数据，零事故。第三页：数据一致性保障，由他负责，方案待确认。

他写完了，看了一遍，保存，没有发出去。

他关掉文档，在记事本里加了一行新的待办事项：明天上午把方案发给纪衡。

他写完了，关掉记事本，关掉电脑，站起来，走进卧室，躺在床上，看着天花板，天花板上有裂缝，物业说，不影响结构。他看了一会儿，闭上眼睛。

他想起易文说的那句话：你写的东西，总是出现在别人的方案里。

他想起自己今天下午写的那份方案，三页纸，放在本地，没有发出去。

他翻了个身，闭上眼睛。

明天。
