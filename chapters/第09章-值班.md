# 第九章 · 值班

周一早上七点五十八分，值班手机响了。

陈稳从床上坐起来，伸手摸到手机，屏幕亮着，显示一条告警推送——结算成功率 99.99%，阈值恢复通知。他把手机放下，躺了两秒，然后坐起来，穿衣服。他走到客厅，倒了一杯水，喝了一口，凉的，从冰箱里拿出来的，胃缩了一下。他放下杯子，看了一眼时间，八点零三分。他换好鞋，从抽屉里拿出那盒胃药，倒了一粒，就着水吞了，然后拿上值班手机，出门。

地铁上人不多，他站着，手扶着栏杆，值班手机握在另一只手里，屏幕朝上。列车进站，刹车的时候，手机震动了一下，他低头看，是值班排班系统的签到通知。他看了一眼，关掉。

他到了公司，刷卡进闸机，等电梯，电梯来了，门打开，里面没有人。他走进去，按了八楼，电梯门关上。电梯在四楼停了一下，门开了，没有人上来，又关上了。

他走到工位，坐下来，打开电脑，打开监控大盘。绿的，平的，结算成功率 99.99%，拦截器正常，一切正常。他看了一眼右下角，值班系统显示已签到，剩余时间二十三小时五十七分钟。

他打开邮箱，看到纪衡的邮件，昨晚十一点四十七分发的，标题是"八月第一周工作安排"。正文不长：本周值班陈稳，周一至周三隔日值班，周四至周日待命。三个转岗同事预计本周一到岗，他负责带。

他关掉邮件，打开 IDE，开始写代码。

九点三十分，走廊上来了三个人，一男两女，背着包，站在工位区中间四处张望。男的戴眼镜，二十三四岁，背黑色双肩包，手里拿着一份打印文件。

"你好，请问结算组是在这里吗？"他说。

"嗯。"陈稳说。

"我们是转岗过来的，今天报到。"

陈稳站起来，指了指旁边那排空工位——老梁的工位，和旁边两个空位，已经放了新显示器，键盘鼠标还没拆封。三个人走过去，男的自我介绍叫王磊，短头发戴圆框眼镜的女生叫林晓，长头发扎马尾的女生叫张悦。林晓说她在营销技术部做了三年后端，主要做对账模块，张悦是今年六月刚入职的应届生。

陈稳说："先装环境。JDK 十七，Maven，Git，IDE。有问题问我。"

他回到工位，继续写代码。十一分钟后，值班手机响了，来电显示座机号，他接起来。

"你好，结算组值班，陈稳。"

"运营部的。商户反馈对账数据对不上，差两千三。"

"商户编号。"

"M202-4437-1。"

陈稳打开查询页面，输入编号，按回车。页面加载了两秒，显示最近一笔结算记录——凌晨三点四十七分，金额四万三千二，已结算。他告诉对方这笔记录，对方说商户显示的是四万零九百。陈稳打开结算流水表，从上往下看，发现还有一笔四万零九百的，结算时间晚了两分钟，类型是人工补结。他让运营去问商户结算日后是不是有一笔退款。电话挂断。

他放下手机，继续写代码。

下午一点，值班手机震动，告警推送——结算队列积压超过阈值，当前积压 1,847 条，阈值 1,500 条。

他打开监控，看到积压线在缓慢上升，每分钟增加大约三十到四十条。下午一点不是结算高峰期。他打开日志，看到请求来源是营销系统的促销活动结算——昨天上线了一个活动，今天开始产生结算请求，请求量超出预期。

他打开营销结算 adapter 的配置文件，看到一行：

```
# marketing.settle.throttle.enabled=false
```

限流默认关闭。

他打开配置文件，把限流开关打开，阈值设为 1,200 条每分钟，保存，重启适配器。监控上，积压到 1,900 条后开始下降，三分钟降到 1,100 条。

他打开记事本，记了一行："营销结算适配器限流已开启，阈值 1200/min。"

下午三点，他站起来，走到茶水间接水。走回来的时候，经过王磊的工位，王磊正在看代码，屏幕上显示结算系统的配置类。林晓的桌上放着两本书，《Java 并发编程实战》和《分布式系统设计》，书脊已经开了。张悦的电脑上显示一个 Git 教程页面，停留在第十步。

他走回工位，继续写代码。他写了一个配置项转换工具，把 Properties 格式转成 JSON，方便监控展示。他写了一个递归解析的方法，处理嵌套配置，试了三次，第一次递归深度不够，第二次类型转换报错，第三次才跑通。写完，跑了一遍测试，全部通过，提交。

下午六点，他点了一份外卖，一份炒饭，鸡蛋火腿青豆，上面盖着一层油。他坐在工位上吃，吃了一半，值班手机响了，运维组打来的，确认限流是他开的。他说是，电话挂断。他继续吃，把剩下的吃完，把饭盒扔进垃圾桶，回到工位。

晚上九点，他站起来，走到窗边，看着楼下。路灯亮着，对面那栋楼，亮着灯的窗户不多。三楼亮着，五楼亮着，七楼亮着，八楼亮着，九楼亮着。他看了十一个月的那扇窗，还是黑的。

他站了一会儿，走回工位，继续写代码。他打开邮箱，看到纪衡的邮件，晚上八点四十七分："拦截器已全量运行四十八小时，累计拦截 4,217 次，0 资损。周五前出报告。另，三个转岗同事的学习计划，每天下班前发一份进度。"

他打开记事本，写了一份学习计划：周一，环境搭建与系统架构概览。周二，结算核心链路源码阅读。周三，拦截器配置与测试。周四，结算队列与限流机制。周五，值班流程与告警处理。

他写完了，保存。

晚上十一点，他收拾东西回家。走出电梯，穿过大厅，刷卡出闸机，往地铁站走。值班手机握在手里，屏幕朝上，指节泛白。地铁来了，他走进去，找了个靠门的位置站着，手扶着栏杆，列车在隧道里穿行，窗户外面是黑色的，偶尔有光照进来，是站台上的灯。

他回到家，换了鞋，坐下来，看了一眼值班系统，剩余时间十六小时十一分钟。他走到卧室，躺下来，闭上眼睛。

睡着之前，手机响了，告警音。他从床上坐起来，拿起手机，看到告警推送——结算成功率降至 99.60%，持续下降中。

他坐起来，穿好衣服，走到客厅，看了一眼时间，凌晨一点二十三分。他打开监控大盘，看到结算成功率从 99.99% 开始下降，十五分钟内降到 99.60%，还在降。打开日志，异常类型全部是"数据库连接超时"。

他打开数据库连接池监控，使用率 97%，活动连接数 194，最大连接数 200。等待队列里有十二个请求在等连接，最长的已经等了七秒多。

他打开慢查询日志，看到一条查询语句的执行时间从三十毫秒增加到三秒，每分钟调用超过两百次。他复制了那条查询，打开数据库分析页面，执行了四秒，扫描超过一千万行数据。

他打开表结构，发现是 settle_reconciliation 表，查询条件中的字段没有索引。他打开 DDL 历史，看到这个表是上周四创建的，经办人叫张毅——老梁在技术支持中心的交接人。

他给那两个字段添加了联合索引。ALTER TABLE 执行了三秒，索引创建成功。监控上，连接池使用率从 97% 降到 70%，结算成功率五分钟内恢复到 99.99%。

他打开记事本，记了一行记录："2026-08-03 01:23 结算成功率降至 99.60%，根因：settle_reconciliation 表缺少索引，连接池已被打满。已添加联合索引，系统已恢复。建议：DDL 审批流程增加索引检查。"

他记完，看了一眼时间，凌晨一点四十一分。他回到卧室，躺下来，闭上眼睛，面朝墙壁，听到自己的心跳，跳得很慢，一下，两下，三下，然后他睡着了。

第二天早上，他到了公司，八点三十分，工位区已经有人了。王磊的显示器亮着，屏幕上是一张结算系统架构图，用 draw.io 画的，画了三小时，二十多个节点，每条线上标了方法名和参数。林晓在看代码，桌上放着一杯咖啡，杯沿有口红印。张悦的 Git 教程从第十步翻到了第十六步。

陈稳坐下来，打开邮箱，看到纪衡的邮件，早上七点十二分："凌晨告警看到了。处理方式正确。DDL 审批流程改进建议，周五前提交书面方案。"

他关掉邮件，在昨天的学习计划后面加了一行："周五，DDL 审批流程改进方案。"

上午九点，王磊走过来，手里拿着一份打印出来的代码，订书机订了两下，大概五十页。他说有一段状态机转换逻辑看不明白，结算状态从已提交到已确认的转换，中间有一个条件判断，调用了另一个方法，又调用了配置类，整个流程不清楚。

陈稳看了十几秒，说："状态机定义在 SettleStateMachine 里。转换规则在里面。"

王磊回到工位，开始搜索那个文件。二十分钟后，陈稳站起来，走到王磊的工位，看到王磊正在看 SettleStateMachine 的代码，光标停在一行配置上。

"看到了？"陈稳说。

"嗯，转换规则找到了。但条件判断里的方法调用了哪个配置类？"

陈稳说 SettleConfig，在 config 包里。

王磊打开 config 包，找到 SettleConfig 类，看了一遍，说找到了配置项 settle.state.transition.timeout，问默认值。陈稳说三千六百秒。王磊说一个小时。陈稳说嗯。

陈稳走回工位，继续写代码。

下午两点，林晓走过来，坐在旁边的椅子上，问了对账模块的数据源。陈稳告诉她是 settle_db 从库，延迟三十秒以内不处理。她点了点头，站起来，走回工位。

下午四点，值班手机响了。陈稳接起来。

"你好，结算组值班，陈稳。"

"数据组，易文。你们系统今天凌晨有个告警，数据库连接池打满，你修了。那条慢查询是哪个表？"

"settle_reconciliation。"

"谁创建的？"

"张毅。"

"老梁的交接人？"

"嗯。"

"这个表上周四创建的，没有文档，没有设计评审，没有索引。"电话那头顿了一下，"张毅不会犯这种低级错误。"

陈稳没有说话。

"你这个索引加得及时。但问题是为啥没有索引就上线了。"

"DDL 审批流程没有检查索引。"

"那你打算怎么办。"

"周五前提交改进方案。"

"纪衡让你写的？"

"嗯。"

"写完之后给我看一下。"

"好。"

"挂了。"

电话挂断。陈稳放下手机，继续写代码。

晚上七点，他收拾东西，走到电梯口，等电梯，电梯来了，门打开，里面站着一个人，白衬衫，黑西裤，黑框眼镜，是顾源。

"你好。"陈稳说。

"你好。"顾源说。

陈稳走进去，按了一楼，电梯门关上。

"值班？"顾源说。

"嗯。"

"昨天凌晨那个告警，我看到了。数据库连接池打满，你加了索引，恢复了。"

"嗯。"

"你知道那个表是谁创建的吗？"

"张毅。"

"张毅以前是运维组的，做 DBA 的，代码能力一般，但他不会犯这种低级错误。"

陈稳看着电梯门上的数字，六楼，五楼。

"我做了一个实验。你回去查一下那个表的创建时间和最后一次修改时间，对比一下。"

陈稳看了顾源一眼，说："好。"

到了一楼，电梯门打开，顾源先走出去，走了两步，回头说："有人改过那个表的结构。你回去查一下 binlog。"

顾源走了出去，穿过大厅，刷卡出闸机，消失在门外。

陈稳走出电梯，穿过大厅，刷卡出闸机，站在门外，路灯亮着，风不大，吹过来带着一点凉意。他站了一会儿，然后往地铁站的方向走。

他回到家，换了鞋，直接走到书房，打开电脑，连接到数据库，查询 settle_reconciliation 表的创建时间和最后一次修改时间。

创建时间：2026-07-28 16:32:17
修改时间：2026-08-01 23:14:42

他打开 binlog，查了一下那个时间点附近的记录。

操作类型：ALTER TABLE
操作人：root@localhost
操作内容：DROP INDEX `idx_xxx`

他看了三遍。然后他打开 Git 日志，查了一下 2026-08-01 附近的提交记录，没有找到任何涉及这个表索引的提交。

他关掉终端，在椅子上坐了一会儿，没有动。然后他打开记事本，加了一行：

"2026-08-03 22:47 settle_reconciliation 表索引被人为删除，操作人 root@localhost，时间 2026-08-01 23:14，无对应 Git 提交。需确认操作人身份。"

他看了一眼那行字，然后关掉记事本，站起来，走到窗边，拉开窗帘。

对面那栋楼，亮着灯的窗户不多。三楼亮着，五楼亮着，七楼亮着，八楼亮着，九楼亮着。他看了十一个月的那扇窗，还是黑的。

他站了一会儿，放下窗帘，走回卧室，躺下来，闭上眼睛。

他想起顾源说的那句话——"有人改过那个表的结构。"

他想起那条被删除的索引，没有 DDL 审批，没有 Git 提交，没有记录。

他翻了翻身，面朝墙壁，盯着墙上的光，从窗帘缝隙里漏进来，在天花板上拉出一条细长的白色线条。

他闭上眼睛，没有睡着。

过了很久，他拿出手机，看了一眼时间，凌晨零点十一分。他打开备忘录，写了一行字："明天查 binlog，确认操作人 IP。"

然后他关了手机，把手机放在床头柜上，屏幕朝下，翻了个身，面朝天花板，盯着天花板上那道细长的光，闭上了眼睛。
